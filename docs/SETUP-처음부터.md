# 처음부터 따라 하는 작업환경 만들기

**밥친구 잇플 · Eatple** 개발환경을 본인 컴퓨터에 만드는 방법입니다.
프로그래밍을 모르셔도 그대로 따라 하면 됩니다. 처음 한 번만 **20~30분**
걸리고, 그 뒤로는 2분이면 시작합니다.

이 문서에서 하는 일:

1. 프로그램 3개 설치 (Node.js, Git, Claude Code)
2. 프로젝트 파일 내려받기
3. 잘 되는지 확인
4. 클로드에게 인수인계 받기
5. 작업한 것 올리기

> **미리 안심하셔도 되는 것**
> - 돈 드는 것 없습니다. 전부 무료입니다.
> - 비밀번호를 어딘가에 적어 넣는 단계는 없습니다.
> - 뭔가 잘못돼도 여러분 컴퓨터나 서비스가 망가지지 않습니다.
>   최악의 경우 폴더를 지우고 처음부터 다시 하면 됩니다.

---

## 준비: '터미널'이 뭔지만 알고 가기

앞으로 **명령어를 입력하는 검은 창**을 쓰게 됩니다. 이걸 터미널이라고 합니다.
마우스로 클릭하는 대신 글자로 명령하는 창이라고 생각하시면 됩니다.

**Windows에서 여는 법**
1. 키보드에서 **Windows 키**를 누릅니다
2. `terminal` 이라고 칩니다
3. **터미널**(또는 **Windows PowerShell**)을 클릭합니다

**Mac에서 여는 법**
1. **Command(⌘) + 스페이스** 를 누릅니다
2. `terminal` 이라고 칩니다
3. **터미널**을 클릭합니다

검은(또는 파란) 창이 뜨고 커서가 깜빡이면 준비 완료입니다.

**이 문서를 읽는 법**: 아래처럼 회색 상자에 있는 글자는 터미널에 **그대로
복사해서 붙여넣고 Enter**를 치라는 뜻입니다.

```
이런 상자
```

> 터미널에 붙여넣기는 `Ctrl + V`(Mac은 `⌘ + V`)입니다. 오른쪽 클릭으로도
> 됩니다. 붙여넣어도 아무 표시가 안 나면 이미 붙여넣어진 것이니 Enter를
> 쳐보세요.

## 1단계. 프로그램 3개 설치

### 1-1. Node.js — 앱을 실행시키는 엔진

**Windows**: 터미널에 아래를 붙여넣고 Enter.

```
winget install OpenJS.NodeJS.LTS
```

설치 중 "이 앱이 장치를 변경하도록 허용하시겠어요?"가 뜨면 **예**를 누르세요.

**Mac 또는 winget이 안 될 때**: https://nodejs.org 에 접속해서 왼쪽의
**LTS** 버튼을 눌러 받은 뒤, 받은 파일을 실행하고 계속 **다음**을 누르면
됩니다.

> ⚠️ **설치가 끝나면 터미널 창을 닫고 새로 여세요.** 안 그러면 방금 깐
> 프로그램을 컴퓨터가 아직 모릅니다. 이 문서에서 제일 많이 하는 실수입니다.

### 1-2. Git — 팀과 파일을 주고받는 도구

**Windows**:

```
winget install Git.Git
```

**Mac 또는 winget이 안 될 때**: https://git-scm.com/downloads 에서 받아
설치합니다. 설치 중 선택지가 많이 나오는데 **전부 기본값으로 다음**을
누르시면 됩니다.

설치 후 **터미널을 다시 닫았다 여세요.**

### 1-3. Claude Code — 같이 작업할 AI

https://claude.com/claude-code 에 접속해 본인 운영체제용 설치 방법을 따라
하세요. 설치 후 터미널을 다시 열고, 나중에 처음 실행할 때 브라우저로
로그인하게 됩니다. 그때 **팀 계정**으로 로그인하세요.

### 1-4. 셋 다 잘 깔렸는지 확인

터미널(새로 연 창)에 하나씩 넣어보세요.

```
node -v
```
```
git --version
```

이렇게 나오면 성공입니다 (숫자는 달라도 됩니다):

```
v24.19.0
git version 2.55.0
```

**`'node'은(는) 내부 또는 외부 명령... 이 아닙니다` 같은 에러가 나오면**
→ 터미널을 닫고 새로 열어보세요. 그래도 안 되면 설치가 안 된 것이니 1-1을
다시 하세요.

> Node.js 버전이 **20 이상**이면 됩니다. `v18`처럼 낮으면 1-1을 다시 하세요.

## 2단계. 프로젝트 파일 내려받기

### 2-1. 어디에 둘지 정하기

바탕화면에 두겠습니다. 터미널에 붙여넣으세요.

**Windows와 Mac 모두 같습니다**
```
cd ~/Desktop
```

`~` 는 "내 사용자 폴더"라는 뜻이라 두 운영체제에서 똑같이 동작합니다.

> **"경로를 찾을 수 없습니다"가 나오면** 바탕화면 폴더 이름이 한글
> (`바탕 화면`)이라 그럴 수 있습니다. 그때는 아래로 하세요. 바탕화면 대신
> 사용자 폴더에 만들어질 뿐, 작업에는 아무 지장이 없습니다.
> ```
> cd ~
> ```
> 이 경우 앞으로 나오는 `~/Desktop/eatple` 은 `~/eatple` 로 읽으시면 됩니다.

### 2-2. 내려받기

```
git clone https://github.com/eatple0701-stack/test.git eatple
```

13MB 정도라 금방 끝납니다. `Cloning into 'eatple'...` 로 시작해서 몇 줄
나오면 성공입니다.

> 로그인을 안 물어봅니다. 받는 것은 누구나 할 수 있게 공개돼 있어서요.
> **올릴 때만** 로그인이 필요하고, 그건 5단계에서 합니다.

### 2-3. 그 폴더로 들어가기

```
cd eatple
```

터미널 왼쪽에 `eatple`이 보이면 안에 들어온 겁니다.

### 2-4. 부품 설치

```
npm install
```

**1~3분 걸립니다.** 글자가 많이 지나가고 중간에 노란 경고가 나와도
정상입니다. 커서가 다시 깜빡이면 끝난 겁니다.

### 2-5. 안전장치 켜기

```
git config core.hooksPath .githooks
```

아무 반응이 없는 게 정상입니다.

> 이건 실수로 **다른 프로젝트 저장소에 이 앱을 올려버리는 사고**를 막는
> 장치입니다. 2026년 8월 2일에 실제로 그 사고가 나서 다른 앱의 실서비스가
> 몇 시간 동안 엉뚱한 화면을 보여줬습니다. 컴퓨터마다 한 번씩 켜줘야 합니다.

## 3단계. 잘 되는지 확인

### 3-1. 자동 검사 돌리기

```
npm test
```

30초쯤 걸립니다. 마지막에 이렇게 나오면 **성공**입니다:

```
ℹ tests 579
ℹ pass 579
ℹ fail 0
```

`fail 0` 이면 완벽합니다. (579라는 숫자는 나중에 늘어날 수 있습니다.)

### 3-2. 앱 실제로 띄워보기

```
npm run dev
```

이렇게 나옵니다:

```
  ➜  Local:   http://localhost:5177/
```

**화면에 실제로 찍힌 그 주소**를 브라우저에 넣으세요. 보통 5177인데, 그 번호를
다른 프로그램이 쓰고 있으면 5178처럼 다른 번호가 나옵니다. 둘 다 정상입니다 —
중요한 건 내 화면에 나온 번호를 쓰는 것입니다.

들어가면 밥친구 앱이 뜹니다.
🎉 여기까지 오셨으면 작업환경이 완성된 겁니다.

**끄는 법**: 터미널에서 `Ctrl + C` (Mac도 `Ctrl + C`).

> **로컬에서 보이는 밥상은 그 브라우저에만 저장됩니다.** 진짜 공유되는
> 데이터를 보려면 배포된 사이트 https://eatple.vercel.app 를 쓰세요.
> 이건 정상이고, 실수로 실제 데이터를 건드리지 않게 하는 안전장치이기도
> 합니다.

## 4단계. 클로드에게 인수인계 받기

프로젝트 폴더 안에서(2-3단계에서 들어간 그 상태) 터미널에 이렇게 칩니다.

```
claude
```

처음이라면 브라우저가 열리며 로그인을 요청합니다. **팀 계정**으로
로그인하세요.

클로드가 준비되면 **첫 메시지로 이걸 그대로 붙여넣으세요**:

```
docs/HANDOVER.md 를 읽고 이 프로젝트를 인수인계 받아.
읽고 나서 현재 상태 요약이랑 지금 해야 할 일을 나한테 보고해줘.
```

클로드가 프로젝트 전체를 파악해서 보고해 줍니다. 그다음부터는 한국어로
편하게 시키시면 됩니다. 예:

- `장소 목록 화면에서 글씨가 너무 작아. 키워줘`
- `지금 앱에서 제일 급하게 고쳐야 할 게 뭐야?`
- `밥상 만드는 화면 한번 열어서 보여줘`

> 작업 규칙(`CLAUDE.md`)은 그 폴더에서 클로드를 켜면 **자동으로 읽힙니다.**
> 따로 시킬 필요 없습니다.

## 5단계. 작업한 것 올리기

작업이 끝났으면 팀에게 공유해야 합니다. 클로드에게 시켜도 되고, 직접 쳐도
됩니다.

```
git add -A
```
```
git commit -m "무엇을 바꿨는지 한 줄"
```
```
git push
```

**처음 `git push` 할 때만** GitHub 로그인을 물어봅니다. 브라우저 창이 뜨면
**팀 계정(eatple0701-stack)** 으로 로그인하세요.

올리고 나면 **1~2분 뒤 https://eatple.vercel.app 에 자동으로 반영**됩니다.
따로 배포할 필요 없습니다.

> 🔒 **비밀번호를 클로드에게 알려주지 마세요.** 로그인은 브라우저에서
> 사람이 직접 하는 일입니다. 클로드는 안내만 합니다.

## 두 번째부터는 이렇게

컴퓨터를 껐다 켠 다음 다시 작업할 때:

```
cd ~/Desktop/eatple
```
(2단계에서 `cd ~` 로 하셨다면 `cd ~/eatple`)

```
git pull
```
```
claude
```

**`git pull` 은 매번 작업 시작 전에 하세요.** 다른 사람이 한 작업을 받아오는
명령입니다. 이걸 빼먹고 작업하면 나중에 충돌이 나서 번거로워집니다.

정리하면 이 습관 두 개면 됩니다:

- 시작할 때 **`git pull`**
- 끝날 때 **`git push`**

## 막혔을 때

**`npm install` 이 빨간 에러를 잔뜩 냄**
인터넷 연결을 확인하고 한 번 더 실행해 보세요. 그래도 안 되면 `eatple`
폴더를 통째로 지우고 2단계부터 다시 하시면 됩니다. 지워도 아무 문제
없습니다 — 원본은 GitHub에 있으니까요.

**`git push` 가 `push refused` 라고 거부함**
2-5단계의 안전장치가 막은 겁니다. 주소가 맞는지 확인해 보세요:
```
git remote -v
```
`eatple0701-stack/test` 가 보여야 정상입니다. 다르면 클로드에게
"remote 주소가 이상해, 고쳐줘" 하고 화면을 보여주세요.

**`npm test` 에서 `fail` 이 0이 아님**
방금 뭔가 고치다가 그렇게 됐다면, 클로드에게 "테스트가 실패해, 봐줘" 하고
시키세요. 아무것도 안 고쳤는데 실패한다면 `git pull` 로 최신을 받아보세요.

**터미널에서 한글이 깨져 보임**
Windows 터미널이면 대부분 괜찮습니다. 옛날 `cmd` 창이면 깨질 수 있으니
**Windows 터미널**이나 **PowerShell**을 쓰세요.

**뭘 해야 할지 모르겠음**
클로드에게 물어보세요. `지금 상황 알려줘` 나 `내가 뭘 해야 해?` 라고 치면
됩니다. 이 문서에 없는 것도 대부분 답해 줍니다.
