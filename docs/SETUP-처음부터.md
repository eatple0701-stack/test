# 처음부터 따라 하는 작업환경 만들기

**밥친구 잇플 · Eatple** 개발환경을 본인 컴퓨터에 만드는 방법입니다.
프로그래밍을 모르셔도 그대로 따라 하면 됩니다. 처음 한 번만 **20~30분**
걸리고, 그 뒤로는 2분이면 시작합니다.

이 문서에서 하는 일:

1. 프로그램 3개 설치 + Git에 내 이름 알려주기
2. 프로젝트 파일 내려받기
3. 잘 되는지 확인
4. 클로드에게 인수인계 받기
5. 작업한 것 올리기

> **미리 안심하셔도 되는 것**
> - 여러분이 결제할 일은 없습니다. Node·Git·저장소는 무료이고, Claude
>   Code 요금은 팀 계정에 붙어 있습니다.
> - 비밀번호를 터미널이나 파일에 적어 넣는 단계는 없습니다. 로그인은 전부
>   브라우저에서 사람이 직접 합니다.
> - **1~4단계는 뭘 해도 안 망가집니다.** 최악의 경우 폴더를 지우고 처음부터
>   다시 하면 됩니다.
>
> ⚠️ **5단계만 다릅니다.** `git push` 로 올린 것은 **1~2분 뒤 실서비스에
> 아무 검사 없이 그대로 반영**됩니다. 폴더를 지워도 되돌아가지 않습니다.
> 그래서 5단계에는 올리기 전 확인 절차가 따로 있습니다.

## 준비: '터미널'이 뭔지만 알고 가기

앞으로 **명령어를 입력하는 검은 창**을 쓰게 됩니다. 이걸 터미널이라고 합니다.
마우스로 클릭하는 대신 글자로 명령하는 창이라고 생각하시면 됩니다.

**Windows에서 여는 법**
1. 키보드에서 **Windows 키**를 누릅니다
2. `terminal` 이라고 칩니다
3. **터미널**(또는 **Windows PowerShell**)을 클릭합니다

**Mac에서 여는 법**
1. **Command(⌘) + 스페이스** 를 누릅니다
2. `terminal` 이라고 칩니다
3. **터미널**을 클릭합니다

검은(또는 파란) 창이 뜨고 커서가 깜빡이면 준비 완료입니다.

> **시작 전에 팀에서 받아둘 것 — 로그인 정보 2개**
> 이 문서는 1-3, 4단계, 5단계에서 **팀 계정** 로그인을 요구합니다.
> - **Claude Code 계정** (4단계에서 사용)
> - **GitHub 팀 계정** `eatple0701-stack` (5단계에서 사용)
>
> 브라우저에 이미 로그인된 **개인 계정으로 진행하면 5단계에서 막힙니다.**
> 팀에 먼저 물어보고 시작하세요. 비밀번호를 이 문서 어딘가에 적어 넣는
> 일은 없고, 전부 브라우저 로그인 창에서 처리됩니다.

**이 문서를 읽는 법**: 회색 상자에 있는 글자는 터미널에 **그대로 복사해서
붙여넣고 Enter**를 치라는 뜻입니다.

```
이런 상자
```

> 터미널에 붙여넣기는 `Ctrl + V`(Mac은 `⌘ + V`)입니다. 오른쪽 클릭으로도
> 됩니다. 붙여넣어도 아무 표시가 안 나면 이미 붙여넣어진 것이니 Enter를
> 쳐보세요.
>
> **Windows 상자와 Mac 상자가 따로 있으면 본인 것만** 쓰세요. 표시가 없는
> 상자는 두 운영체제 공통입니다.

## 1단계. 프로그램 3개 설치

### 1-1. Node.js — 앱을 실행시키는 엔진

**Windows**

```
winget install OpenJS.NodeJS.LTS
```

설치 중 "이 앱이 장치를 변경하도록 허용하시겠어요?"가 뜨면 **예**를 누르세요.

**Mac** (또는 winget이 안 되는 Windows): https://nodejs.org 에 접속해 왼쪽의
**LTS** 버튼으로 받은 뒤, 받은 파일을 실행하고 계속 **다음**을 누르면 됩니다.

> ⚠️ **설치가 끝나면 터미널 창을 닫고 새로 여세요.** 안 그러면 방금 깐
> 프로그램을 컴퓨터가 아직 모릅니다. 이 문서에서 제일 많이 하는 실수입니다.

### 1-2. Git — 팀과 파일을 주고받는 도구

**Windows**

```
winget install Git.Git
```

설치 중 선택지가 많이 나오는데 **전부 기본값으로 다음**을 누르시면 됩니다.

**Mac** — 받을 설치 파일이 없습니다. 터미널에 이것만 치세요.

```
xcode-select --install
```

`명령어 라인 개발자 도구를 설치하시겠습니까?` 창이 뜨면 **설치**를 누르고
5~10분 기다립니다. `이미 설치되어 있습니다` 가 나와도 정상이니 넘어가세요.
(Git이 이 안에 들어 있습니다.)

설치 후 **터미널을 다시 닫았다 여세요.**

### 1-3. Claude Code — 같이 작업할 AI

https://claude.com/claude-code 에서 본인 운영체제용 설치 방법을 따라 하세요.
설치 후 터미널을 다시 열면 되고, 로그인은 4단계에서 브라우저로 합니다.
그때 **팀 계정**으로 로그인하세요.

### 1-4. 셋 다 잘 깔렸는지 확인

새로 연 터미널에 하나씩 넣어보세요.

```
node -v
```
```
git --version
```

이렇게 나오면 성공입니다 (숫자는 달라도 됩니다):

```
v24.19.0
git version 2.55.0
```

**에러가 나오면** (`'node'은(는) 내부 또는 외부 명령... 이 아닙니다`,
`command not found: node`) → 터미널을 닫고 새로 열어보세요. 그래도 안 되면
설치가 안 된 것이니 1-1을 다시 하세요.

> Node.js 버전이 **22 이상**이면 됩니다. LTS를 받으셨으면 자동으로 만족합니다.

### 1-5. 내가 누군지 Git에 알려주기

Git은 기록을 남길 때마다 "누가 했는지" 이름표를 붙입니다. 이걸 안 정해두면
5단계에서 `git commit` 이 **거부됩니다.**

> ⚠️ **이 문서에서 따옴표 안을 바꿔서 넣는 곳은 여기 딱 한 군데입니다.**
> 다른 상자는 전부 그대로 복붙이지만, 아래 두 줄만은 `홍길동` 과
> `hong@inha.edu` 자리에 **본인 이름과 본인 메일**을 넣으세요.

```
git config --global user.name "홍길동"
```
```
git config --global user.email "hong@inha.edu"
```

로그인이 아닙니다. 비밀번호도 아닙니다. 그냥 **커밋에 붙는 이름표**라서
아무 값이나 들어갑니다. 그래서 더더욱 본인 것을 넣어야 합니다 — 팀원이
나중에 "이건 누가 바꾼 거지?" 할 때 보는 게 이 이름입니다.

아무 반응이 없는 게 정상입니다. 확인하려면:

```
git config --global user.name
```

방금 넣은 이름이 나오면 성공입니다.

> 2-5의 안전장치와 달리 **이건 컴퓨터에 한 번만** 하면 됩니다. 폴더를
> 지우고 다시 받아도 그대로 남습니다.

## 2단계. 프로젝트 파일 내려받기

### 2-1. 어디에 둘지 정하기

바탕화면에 두겠습니다.

```
cd ~/Desktop
```

`~` 는 "내 사용자 폴더"라는 뜻이라 Windows·Mac 모두 같습니다.

> **"경로를 찾을 수 없습니다"가 나오면** 바탕화면 폴더 이름이 한글
> (`바탕 화면`)이라 그럴 수 있습니다. 그때는 아래로 하세요. 바탕화면 대신
> 사용자 폴더에 만들어질 뿐, 작업에는 아무 지장이 없습니다.
> ```
> cd ~
> ```
> 이 경우 앞으로 나오는 `~/Desktop/eatple` 은 `~/eatple` 로 읽으시면 됩니다.

### 2-2. 내려받기

```
git clone https://github.com/eatple0701-stack/test.git eatple
```

20MB 조금 안 되게 받으니 금방 끝납니다. `Cloning into 'eatple'...` 로
시작해 몇 줄 나오면 성공입니다.

> 로그인을 안 물어봅니다. 받는 것은 누구나 할 수 있게 공개돼 있어서요.
> **올릴 때만** 로그인이 필요하고, 그건 5단계에서 합니다.

### 2-3. 그 폴더로 들어가기

```
cd eatple
```

터미널 줄 어딘가에 `eatple`이 보이면 안에 들어온 겁니다.

### 2-4. 부품 설치

```
npm install
```

**1~3분 걸립니다.** 글자가 많이 지나가고 중간에 노란 경고가 나와도
정상입니다. 커서가 다시 깜빡이면 끝난 겁니다.

### 2-5. 안전장치 켜기

```
git config core.hooksPath .githooks
```

아무 반응이 없는 게 정상입니다.

> 이건 실수로 **다른 프로젝트 저장소에 이 앱을 올려버리는 사고**를 막는
> 장치입니다. 2026년 8월 2일에 실제로 그 사고가 나서 다른 앱의 실서비스가
> 몇 시간 동안 엉뚱한 화면을 보여줬습니다.
>
> **폴더(클론)마다 한 번씩** 켜줘야 합니다. git 설정이라 저장소를 따라오지
> 않아요 — 폴더를 지우고 다시 받았다면 이 줄을 **다시** 실행하세요.

## 3단계. 잘 되는지 확인

### 3-1. 자동 검사 돌리기

```
npm test
```

**1분쯤 걸립니다.** 중간에 멈춘 것처럼 보여도 기다리세요. 마지막에 이렇게
나오면 **성공**입니다:

```
ℹ tests 726
ℹ pass 726
ℹ fail 0
```

`fail 0` 이면 완벽합니다. (726라는 숫자는 나중에 늘어날 수 있습니다.)

### 3-2. 앱 실제로 띄워보기

```
npm run dev
```

이렇게 나옵니다:

```
  ➜  Local:   http://localhost:5177/
```

**화면에 실제로 찍힌 그 주소**를 브라우저에 넣으세요. 보통 5177인데, 그 번호를
다른 프로그램이 쓰고 있으면 5178처럼 다른 번호가 나옵니다. 둘 다 정상입니다 —
중요한 건 내 화면에 나온 번호를 쓰는 것입니다.

들어가면 밥친구 앱이 뜹니다.
🎉 여기까지 오셨으면 작업환경이 완성된 겁니다.

**끄는 법**: 터미널에서 `Ctrl + C` (Mac도 `Ctrl + C`).

> **로컬에서 보이는 밥상은 그 브라우저에만 저장됩니다** — 단, `.env.local`
> 파일이 **없을 때** 얘기입니다. 진짜 공유되는 데이터를 보려면 배포된 사이트
> https://eatple.vercel.app 를 쓰세요.
>
> ⚠️ 누가 `.env.local` 파일을 보내주더라도 **그냥 폴더에 넣지 마세요.** 그
> 안에 Supabase 주소·키가 들어 있으면 로컬 작업이 **실제 파일럿 데이터베이스**
> 를 건드립니다. 로컬이 안전한 건 설정이 없기 때문이지, 앱이 막아주기
> 때문이 아닙니다.

## 4단계. 클로드에게 인수인계 받기

3-2에서 `npm run dev` 를 켜두셨다면 그 터미널은 아직 앱을 돌리는 중이라
명령을 받지 않습니다. **`Ctrl + C` 로 끄거나**, 터미널 창을 새로 열고
`cd ~/Desktop/eatple` 로 다시 들어가세요.

그다음 이렇게 칩니다.

```
claude
```

처음이라면 브라우저가 열리며 로그인을 요청합니다. **팀 계정**으로
로그인하세요.

클로드가 준비되면 **첫 메시지로 이걸 그대로 붙여넣으세요**:

```
docs/HANDOVER.md 를 읽고 이 프로젝트를 인수인계 받아.
읽고 나서 현재 상태 요약이랑 지금 해야 할 일을 나한테 보고해줘.
```

클로드가 프로젝트 전체를 파악해서 보고해 줍니다. 그다음부터는 한국어로
편하게 시키시면 됩니다. 예:

- `장소 목록 화면에서 글씨가 너무 작아. 키워줘`
- `지금 앱에서 제일 급하게 고쳐야 할 게 뭐야?`
- `밥상 만드는 화면 한번 열어서 보여줘`

> 작업 규칙(`CLAUDE.md`)은 그 폴더에서 클로드를 켜면 **자동으로 읽힙니다.**
> 따로 시킬 필요 없습니다.

## 5단계. 작업한 것 올리기

⚠️ **여기서부터는 실서비스에 영향이 갑니다.** 올린 것은 1~2분 뒤
https://eatple.vercel.app 에 아무 검사 없이 반영됩니다.

### 5-1. 올리기 전에 반드시 두 개를 돌리세요

```
npm test
```
```
node scripts/audit-i18n.mjs
```

`fail 0` 과 `0` 이 나와야 올려도 됩니다. **하나라도 실패하면 올리지 마세요.**
클로드에게 `테스트가 실패해, 봐줘` 하고 시키면 됩니다.

### 5-2. 처음 한 번만 — GitHub 로그인 준비

**Mac은 이걸 먼저 해두셔야 합니다.** 안 하면 5-3에서 터미널이
`Password for 'https://github.com':` 를 묻는데, **GitHub 비밀번호는 이제
통하지 않습니다.** 여기서 대부분 막힙니다.

```
gh auth login
```

`gh: command not found` 가 나오면 https://cli.github.com 에서 설치하거나:

```
brew install gh
```

브라우저가 열리면 **팀 계정(eatple0701-stack)** 으로 로그인하세요.
비밀번호를 터미널에 치는 일은 없습니다.

> **Windows**는 Git 설치 때 함께 깔린 도구가 브라우저 창을 띄워주기 때문에
> `gh auth login` 없이 5-3으로 가도 됩니다. 물론 해두셔도 좋습니다.

### 5-3. 올리기

```
git add -A
```
```
git commit -m "무엇을 바꿨는지 한 줄"
```
```
git push
```

올리고 나면 **1~2분 뒤 https://eatple.vercel.app 에 자동으로 반영**됩니다.
따로 배포할 필요 없습니다.

> 🔒 **키 이름 3초 구별법**
> 이 저장소는 **공개**라 올린 것은 누구나 볼 수 있습니다.
> - `sb_publishable_…` — 공개용. 이미 저장소에 들어 있습니다. 괜찮습니다.
> - `sb_secret_…` — **위험.** 어떤 파일에도, 어떤 대화창에도 넣지 마세요.
>
> Supabase 대시보드에서 둘이 나란히 있어 헷갈리기 쉽습니다. `secret` 이라는
> 글자가 보이면 손대지 마세요.
>
> 그리고 **비밀번호는 클로드에게 알려주지 마세요.** 로그인은 브라우저에서
> 사람이 직접 하는 일입니다.

## 두 번째부터는 이렇게

컴퓨터를 껐다 켠 다음 다시 작업할 때:

```
cd ~/Desktop/eatple
```
(2단계에서 `cd ~` 로 하셨다면 `cd ~/eatple`)

```
git pull
```
```
claude
```

**`git pull` 은 매번 작업 시작 전에 하세요.** 다른 사람이 한 작업을 받아오는
명령입니다. 이걸 빼먹고 작업하면 나중에 충돌이 나서 번거로워집니다.

정리하면 이 습관 두 개면 됩니다:

- 시작할 때 **`git pull`**
- 올리기 전 **`npm test`** → 통과하면 **`git push`**

여러 사람이 같이 쓸 때는 실시간 동기화가 아니라 `push`/`pull` 시점에
반영됩니다. 같은 파일을 동시에 고치면 충돌이 나니, 서로 다른 화면이나 기능을
맡으시면 편합니다.

## 막혔을 때

**`npm install` 이 빨간 에러를 잔뜩 냄**
인터넷 연결을 확인하고 한 번 더 실행해 보세요. 그래도 안 되면 `eatple`
폴더를 통째로 지우고 2단계부터 다시 하시면 됩니다. 지워도 아무 문제
없습니다 — 원본은 GitHub에 있으니까요. (**다시 받았으면 2-5도 다시**)

**`git push` 가 `push refused` 라고 거부함**
2-5단계의 안전장치가 막은 겁니다. 주소가 맞는지 확인해 보세요:
```
git remote -v
```
`eatple0701-stack/test` 가 보여야 정상입니다.

> ⚠️ 터미널 메시지에 `.githooks/pre-push` 를 고치라는 안내가 같이 나오는데
> **고치거나 지우지 마세요.** 그 파일이 8월 2일 사고를 막는 장치입니다.
> 거부됐다는 건 후크가 고장 난 게 아니라 **주소가 틀렸다**는 뜻입니다.
> 클로드에게 "remote 주소가 이상해, 고쳐줘" 하고 화면을 보여주세요.

**`git commit` 이 `Author identity unknown` / `Please tell me who you are` 라고 나옴**
1-5를 안 하고 오신 겁니다. 1-5의 두 줄을 (따옴표 안을 **본인 것으로 바꿔서**)
실행하고 `git commit` 을 다시 하세요.

> ⚠️ 그 에러 화면 안에 `git config --global user.email "you@example.com"`
> 이라는 줄이 같이 보입니다. **그걸 그대로 복붙하지 마세요.** 이 저장소는
> 공개라, 팀 기록에 `you@example.com` 이라는 이름으로 영구히 남습니다.
> 이 문서에서 유일하게 "그대로 복붙하면 안 되는" 상자입니다.

> 커밋이 이렇게 실패한 뒤 `git push` 를 치면 에러 없이
> `Everything up-to-date` 만 뜹니다. **올라간 게 아닙니다** — 올릴 커밋이
> 아예 안 만들어진 것이라, 기다려도 사이트는 바뀌지 않습니다.

**`git push` 가 비밀번호를 물어봄**
GitHub 비밀번호는 통하지 않습니다. `Ctrl + C` 로 취소하고 5-2의
`gh auth login` 을 먼저 하세요.

**`npm test` 에서 `fail` 이 0이 아님**
방금 뭔가 고치다가 그렇게 됐다면 클로드에게 "테스트가 실패해, 봐줘" 하고
시키세요. 아무것도 안 고쳤는데 실패한다면 `git pull` 로 최신을 받아보세요.

**터미널에서 한글이 깨져 보임**
옛날 `cmd` 창이면 깨질 수 있으니 **Windows 터미널**이나 **PowerShell**을
쓰세요.

**뭘 해야 할지 모르겠음**
클로드에게 물어보세요. `지금 상황 알려줘` 나 `내가 뭘 해야 해?` 라고 치면
됩니다. 이 문서에 없는 것도 대부분 답해 줍니다.

직접 알려주며 실행하세요:

```
node --env-file=.env.local scripts/seoul-food-api.mjs restaurants
```
