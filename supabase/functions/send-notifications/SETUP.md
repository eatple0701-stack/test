# 이메일 알림 켜는 법 (5분, 대시보드에서만)

알림의 뼈대(아웃박스 테이블 + 트리거)는 `schema.sql`을 실행하면 이미 살아
있습니다. 이 문서는 **실제 발송기**를 켜는 마지막 조각입니다. 켜기 전까지는
보낼 메일이 대시보드의 `notifications` 테이블에 쌓여만 있고, 아무것도
고장나지 않습니다.

## 무엇이 언제 발송되나

| 사건 | 받는 사람 | 왜 |
| --- | --- | --- |
| 자리 요청 도착 | 호스트 | 안 열어보면 12시간 전에 요청이 만료되므로 |
| 승인 / 거절 | 게스트 | 저녁 계획이 이 답에 걸려 있으므로 |
| 밥상 취소 | 좌석 걸린 전원 | 빈 출구에 서 있지 않도록 |
| 신고 접수 | 팀 (pilot_team 테이블의 이메일) | 신고를 아무도 안 읽는 상태를 없애려고 |

## 1. Edge Function 만들기

1. Supabase 대시보드 → 왼쪽 메뉴 **Edge Functions** → **Deploy a new function** (편집기로 만들기)
2. 이름: 정확히 `send-notifications`
3. 이 폴더의 `index.ts` 내용 전체를 붙여넣고 **Deploy**
4. 함수 상세 → 설정에서 **Enforce JWT verification 끄기**
   (트리거의 pg_net 호출은 JWT가 없습니다. 익명 호출로 가능한 최악은
   "메일이 예정보다 일찍 발송됨"뿐 — 읽을 수 있는 것이 없습니다)

## 2. 보내는 메일 계정 연결 (둘 중 하나)

**방법 A — 팀 Gmail (도메인 없이 됨, 추천):**
1. 팀 구글 계정 → myaccount.google.com → 보안 → **2단계 인증** 켜기
2. 같은 화면에서 **앱 비밀번호** 생성 (이름 아무거나, 16자리가 나옴)
3. 대시보드 → Edge Functions → **Secrets**에 추가:
   - `GMAIL_USER` = 팀 지메일 주소
   - `GMAIL_APP_PASSWORD` = 방금 받은 16자리 (띄어쓰기 없이)

하루 약 500통 한도 — 파일럿에 충분합니다.

**방법 B — Resend (도메인이 생기면):**
- resend.com 가입 → 도메인 인증 → API 키 발급 → Secret `RESEND_API_KEY` 추가.
- 도메인 인증 없이는 임의 수신자에게 못 보내므로, 도메인이 없는 지금은 방법 A를 쓰세요.

## 3. 신고 알림 받을 팀 이메일 등록

Table Editor → `pilot_team` → **Insert row** → 팀 이메일 1개 입력.
(비워 두면 신고 알림만 발송 안 되고 나머지는 정상 — 의도된 동작)

## 확인하는 법

아무 계정으로 자리 요청을 하나 넣고 → `notifications` 테이블에 행이 생기고
→ 몇 초 안에 `sent_at`이 찍히고 → 호스트 메일함에 도착하면 끝.
`sent_at`이 계속 비어 있으면: 함수 로그(Edge Functions → Logs)를 보세요 —
Secret 오타가 대부분입니다.
